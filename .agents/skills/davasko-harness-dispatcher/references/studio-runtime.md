# Studio runtime branch

Load this branch for studio profile adoption, Unity execution, source-bound
acceptance or dispatcher distribution. Resolve the explicitly approved absolute
HarnessProtocol repository root, not a relative path from an installed skill.
Read `<HarnessProtocol>/docs/studio-runtime.md` and the selected Unity/distribution
contract linked there.

- Before model-bearing init, select the authorized runtime policy using
  `HARNESS_STUDIO_PROFILE`, `HARNESS_RUN_ID` and `HARNESS_RUN_DIR`. Empty pools
  allow no calls. Deterministic offline work sets `HARNESS_OFFLINE=1` and
  `HARNESS_PROBE_SKIP=1`. A failed external judge does not authorize a native
  subagent; native tools retain the host's separate authorization.
- Reuse supplied decisions and explicit approval for the described task. Do not
  repeat interviews on resume. Preserve reserved spending, accounts, publication,
  destructive and unrelated configuration boundaries.
- Acceptance covers current source, outputs and dependencies. Record explicit
  source roots for multi-repository tasks. Source changes require fresh checks;
  never rewrite receipts or refresh fingerprints by assertion.
- `unityRunner.mjs` accepts an absolute approved JSON request with exact Editor,
  project, method source hash and timeout. Preflight is not compilation; a build
  is not browser acceptance. Respect writer ownership. Uncertain jobs require
  recovery, not blind retries or deletion of locks.
- `webglSmoke.mjs` checks an actual accepted Unity build using input and Unity
  state assertions. DOM/canvas stubs do not count as a player. Device, FPS, total
  memory and release acceptance remain separate checks.
- `skillDistribution.mjs` compares whole trees and applies a reviewed plan hash
  with backups. Matching SKILL.md alone is insufficient.

These are cooperative Harness controls, not an OS sandbox, provider billing cap
or guarantee of autonomous production for arbitrary games.
