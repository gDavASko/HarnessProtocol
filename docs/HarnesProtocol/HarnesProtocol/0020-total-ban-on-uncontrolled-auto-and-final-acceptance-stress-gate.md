# ADR 0020: Тотальный запрет бесконтрольного 'auto' и обязательный Final Acceptance Stress-Gate

## Статус
Принято (Accepted)

## Контекст
В ходе боевой эксплуатации Harness Protocol выявлен критический дефект ложноположительной валидации (False-Positive Verification):
1. Узлы роадмапа, помеченные как `validation_type: "auto"`, слепо полагались на простой `exit code 0` узких юнит-тестов (`L0 short-circuit`), полностью минуя независимого ИИ-Судью (`cli-judge` / LLM Quorum).
2. Юнит-тесты проверяли только изоляцию абстрактных классов, но не проверяли сквозной пользовательский опыт, непрерывность данных, скорость, верстку, обработку поражения/победы и отсутствие ошибок рантайма (`TypeError: this.audio.playHit is not a function`).
3. При завершении всех узлов роадмапа `TaskOrchestratorGraph` мгновенно объявлял задачу завершенной (`COMPLETED`) без сквозного интеграционного стресс-теста и независимой приемочной валидации всего продукта.

## Решение

### 1. Тотальный запрет слепого `auto` без контроля ИИ/Человека
- **Категорический запрет чистого `auto`**: Никакой узел (бэкенд, фронтенд, криптография, инфраструктура, алгоритмы) не может быть закрыт исключительно локальным скриптом без независимой проверки.
- **Обязательная гибридная валидация**:
  - `auto` скрипт запускается для проверки детерминированного контракта (тесты, компиляция, сборка).
  - Сгенерированный код и вывод тестов **обязательно** передаются независимому ИИ-судье (Cross-Family AI Judge / Consensus Quorum) для проверки качества реализации, отсутствия симуляций/заглушек и семантической полноты.
  - При отсутствии доступных внешних судей задача не закрывается "вслепую", а переводится на `Human Gate` (`awaiting_human_validation`).

### 2. Обязательный Final Acceptance Stress-Gate в TaskOrchestratorGraph
- После закрытия последнего тактического узла задача **НЕ** завершается (`status != COMPLETED`), а переходит в мета-узел **`finalAcceptanceStressNode`**.
- В `finalAcceptanceStressNode`:
  1. Запускается полный сквозной стресс-тест всего созданного приложения / системы под нагрузкой.
  2. Запускается независимый приемочный аудит ИИ-судьи на соответствие первоначальным требованиям и референсам (`tactical_master.md`).
  3. **Петля исправления (Remediation Loop)**: Если найден ХОТЯ БЫ ОДИН дефект, зависание, ошибка рантайма или расхождение с референсом:
     - Синтезируются корректирующие узлы (`FIX-*`).
     - Корректирующие узлы добавляются в роадмап.
     - Состояние переводится в `IN_PROGRESS`, и система возвращается в новый виток Ralph Loop.
  4. Задача получает статус `COMPLETED` только тогда, когда Final Acceptance Stress-Gate пройден на 100% без единого замечания.

## Последствия
- Полное исключение "сдачи полуфабрикатов" и галлюцинаций готовности.
- Гарантия 100% сквозной работоспособности и стрессоустойчивости создаваемых систем.
